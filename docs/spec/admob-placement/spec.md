# spec.md — AdMob広告配置方針

## 概要
- `BannerView` を使ったバナー広告の配置画面を定義する
- インタースティシャル広告を表示する自然なタイミングを定義する
- 釣りゲーム本体の操作性を損なわず、誤タップと審査リスクを避ける
- 本仕様は配置方針の定義であり、この時点では実装しない

## 目的
- 広告表示による収益化ポイントを整理する
- プレイヤーの操作中断が少ない画面に広告を限定する
- 釣りプレイ中の誤タップや没入感低下を避ける
- AdMobの一般的な配置ポリシーに沿った実装方針を残す

## 対象
- `Presentation/Shared/Admob/BannerView.swift`
- `Presentation/Shared/Admob/InterstitialViewModel.swift`
- `Presentation/Feature/Home/Screen/HomeScreen.swift`
- `Presentation/Feature/Encyclopedia/Screen/EncyclopediaScreen.swift`
- `Presentation/Feature/CatchHistory/Screen/CatchHistoryScreen.swift`
- `Presentation/Feature/Shop/Screen/ShopScreen.swift`
- `Presentation/Feature/Fishing/Screen/FishingScreen.swift`
- `Presentation/Feature/Fishing/Components/ResultOverlay.swift`

## 対象外
- 広告SDKの導入手順
- AdMob管理画面での広告ユニット作成
- 本番広告IDの管理
- 同意管理プラットフォームの導入
- ATTダイアログやトラッキング設計
- 課金による広告非表示

## バナー広告配置方針
### 基本方針
- バナー広告は静的な閲覧画面または管理画面に配置する
- 画面下部固定を基本とする
- スクロールコンテンツには広告分の下余白を確保する
- 主要ボタン、購入ボタン、ナビゲーション導線の直近には置かない
- 釣りプレイ中の画面には配置しない

### 優先度: 高
#### ショップ画面
- 対象: `ShopScreen`
- 配置候補: 画面下部固定
- 余白候補: 既存の `Color.clear.frame(height: 96 + geometry.safeAreaInsets.bottom)` を活用する
- 理由:
  - 餌一覧を閲覧する画面で、ゲーム操作への干渉が少ない
  - スクロール画面のため下部固定バナーと相性がよい
  - 滞在時間が比較的長くなりやすい
- 注意:
  - 購入ボタンのすぐ下に見える配置は避ける
  - 餌購入の成功確認を広告で遮らない

#### 魚図鑑一覧画面
- 対象: `EncyclopediaScreen`
- 配置候補: 画面下部固定
- 余白候補: 既存の `Color.clear.frame(height: 96 + geometry.safeAreaInsets.bottom)` を活用する
- 理由:
  - 魚の収集状況を確認する閲覧中心の画面
  - 連続タップを要求しない
  - 広告表示がプレイ結果に直接影響しにくい
- 注意:
  - 魚カードの `NavigationLink` と広告を近づけすぎない
  - 魚詳細画面まで広告を出すかは別途判断する

### 優先度: 中
#### 釣果履歴画面
- 対象: `CatchHistoryScreen`
- 配置候補: 画面下部固定
- 理由:
  - 釣果記録の閲覧画面で、操作の邪魔になりにくい
  - 履歴が増えるほどスクロール閲覧との相性がよい
- 注意:
  - `catchHistory` が空の場合は広告表示を避ける
  - 空状態で広告だけが目立つ表示にしない

#### ホーム画面
- 対象: `HomeScreen`
- 配置候補: 画面下部またはメニュー導線から離した固定位置
- 理由:
  - 起動後に必ず表示されるため表示機会が多い
  - 収益性は高くなりやすい
- 注意:
  - `startButton` と `menuGrid` が主要導線のため誤タップリスクがある
  - 初回起動直後から広告を強く見せすぎると体験が悪くなる
  - 実装する場合は他の閲覧画面より優先度を下げる

### 配置しない画面
#### 釣りプレイ画面
- 対象: `FishingScreen`
- 理由:
  - `FishingHitBar` と `TapButton` を使ったリアルタイム操作画面である
  - 連続タップ中の誤タップリスクが高い
  - ゲームの集中を妨げる
  - AdMobポリシー上も操作ボタン付近の配置は避けるべき

## インタースティシャル広告表示方針
### 基本方針
- インタースティシャル広告は自然な区切りでのみ表示する
- プレイ開始前、プレイ中、操作直後の即時表示は避ける
- 毎回表示しない
- 釣り完了回数をカウントし、一定回数ごとに表示する
- 推奨頻度は3〜5回の釣り完了につき1回とする

### 優先度: 高
#### 結果画面からホームへ戻るタイミング
- 対象: `FishingScreen` の `ResultOverlay.onClose`
- タイミング: 結果表示後、ユーザーがホームボタンを押した後
- 表示条件:
  - 釣り完了回数が3〜5回に達している
  - 広告ロード済み
  - 直近表示から十分な間隔がある
- 理由:
  - 1プレイが完了した後の自然な画面遷移である
  - 操作中断の印象が弱い
  - 成功と失敗どちらにも適用できる

#### 結果画面から再挑戦するタイミング
- 対象: `FishingScreen` の `ResultOverlay.onRetry`
- タイミング: 結果表示後、ユーザーが再挑戦ボタンを押した後
- 表示条件:
  - 釣り完了回数が3〜5回に達している
  - 広告ロード済み
  - 新規魚種獲得直後は避ける
- 理由:
  - ラウンド間の区切りとして自然
  - 釣りプレイ本体を中断しない
- 注意:
  - 毎回表示するとテンポが悪くなる
  - 広告表示後に `restart()` する順序にして、広告裏でゲームが進行しないようにする

### 優先度: 低〜中
#### ショップ画面から離脱するタイミング
- 対象: `ShopScreen`
- タイミング: 餌購入後ではなく、ショップを閉じてホームへ戻る時
- 理由:
  - 購入操作の直後に表示すると結果確認を邪魔する
  - 画面離脱時なら区切りとして扱いやすい
- 注意:
  - 現状は標準の戻る操作を使っているため制御が難しい
  - 専用戻るボタンを設ける場合のみ検討する

## インタースティシャル広告を表示しないタイミング
- アプリ起動直後
- ホーム画面表示直後
- ホームから釣り開始ボタンを押した直後
- 釣りプレイ中
- タップ成功または失敗の瞬間
- 結果オーバーレイ表示と同時
- 魚図鑑カードを開くたび
- 魚詳細から戻るたび
- ショップの購入ボタン押下直後
- 戻るボタンを押すたび

## 推奨実装順
1. ショップ画面にバナー広告を配置する
2. 魚図鑑一覧画面にバナー広告を配置する
3. 釣果履歴が存在する場合のみ釣果履歴画面にバナー広告を配置する
4. 釣り完了回数を管理する広告表示用状態を追加する
5. 結果画面のホーム遷移または再挑戦時にインタースティシャル広告を条件付き表示する
6. 表示頻度と誤タップリスクを実機で確認する

## 完了条件
- バナー広告の配置候補が画面ごとに明確になっている
- 釣りプレイ画面にはバナー広告を配置しない方針が明記されている
- インタースティシャル広告の表示タイミングが結果画面後に限定されている
- 毎回表示を避ける頻度制御方針が明記されている
- ショップ購入直後やプレイ中など避けるべきタイミングが明記されている
