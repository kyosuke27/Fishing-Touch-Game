# 画像組み込み作業 Spec

## 目的

- `Fising-Touch-Game/Assets.xcassets/img` 配下の画像アセットを、現在の各画面 UI に段階的に組み込む。
- 画面ごとにレビューを挟みながら作業できるよう、実装単位を画面別タスクとして分割する。
- 途中中断しても次に着手する範囲が明確な状態にする。

## 前提

- 現在の画面実装は主に [ContentView.swift](/Users/kyosuke/swift/Fising-Touch-Game/Fising-Touch-Game/ContentView.swift) に集約されている。
- 現在の UI は `systemImage` と図形ベースの表示が多く、画像アセットへの差し替え余地がある。
- 画像アセットは `Fising-Touch-Game/Assets.xcassets/img` 配下に配置されている。
- 作業は 1 画面ずつ進め、各画面の反映後にレビューを実施する。

## 現状の差分整理

- `GameMaster` 上で現在利用している魚は `メダカ`、`アジ`、`タイ` の 3 種のみ。
- 画像アセットには `Buri`、`Isaki`、`Kanpati` など、現行マスタ未使用の画像が含まれる。
- 餌は `normal_bait` と `premium_bait` の 2 種だが、画像アセットは `Esa`、`Ebi`、`Sakana-Esa` など複数ある。
- そのため、今回の作業はまず「既存画面へ画像を組み込む」ことを優先し、未使用アセットの活用は別判断とする。

## 実装方針

- 画像差し替えは画面ごとに完結させる。
- 1 タスクごとに「対象画面」「差し替え対象 UI」「使用予定アセット」「レビュー観点」を定義する。
- 画像名の直接埋め込みを避けるため、必要に応じて画像参照用の定数化またはモデルとのマッピングを追加する。
- 既存レイアウトを大きく壊さず、まずは画像が自然に表示される状態を優先する。
- レビューで問題があれば、その画面単位で手戻り可能な状態を維持する。

## 画面別タスク

### Task 1: ホーム画面

#### 対象

- `HomeView`
- `StatusPill`
- `HomeMenuButton`
- `DecorativeFish`

#### 目的

- ホーム画面を画像ベースの見た目に置き換える。

#### 差し替え候補

- 背景: `HomeBackground`
- タイトル: `Logo`
- 釣り開始ボタン: `StartFishing`
- 魚図鑑導線: `FishList`
- ショップ導線: `ShopButton`
- コイン表示: `Coin`
- 餌表示: `Esa` または `Ebi`
- 装飾魚: `Fish` または魚種画像

#### 作業内容

- `OceanBackground()` ベースの見せ方と `HomeBackground` の共存方法を決める。
- タイトルテキストを `Logo` 中心の表示へ調整する。
- `釣りを始める` ボタンを `StartFishing` ベースに差し替える。
- メニューカードのうち、画像化できるものをアセットで置き換える。
- ステータス表示の `systemImage` を画像アセットへ差し替える。

#### レビュー観点

- ホーム画面として情報優先順位が崩れていないか。
- ボタン画像がタップ可能領域と視覚的に一致しているか。
- 背景画像と文字のコントラストが不足していないか。

#### 完了条件

- ホーム画面で主要導線とステータス表示が画像アセット中心に置き換わっている。
- ボタン導線の視認性が維持されている。

### Task 2: 釣り画面

#### 対象

- `FishingView`
- `CounterCard`

#### 目的

- 釣りプレイ中の魚表示とアクション導線を画像ベースにする。

#### 差し替え候補

- 狙い魚表示: `Medaka`、`Tai`、`Fish`
- 餌表示: `Esa`、`Ebi`
- タップ導線: `BlueButton` または `StartFishing`
- 補助装飾: `Coin`

#### 作業内容

- `FishBadge` の `systemImage` 依存を外し、魚画像を表示できるようにする。
- プレイ中の餌ステータス画像を差し替える。
- `タップ` ボタンを画像ボタンへ差し替えるか、画像付きレイアウトへ変更する。
- プレイ体験を阻害しない範囲で情報量を整理する。

#### レビュー観点

- タップアクションの判別性が十分か。
- 魚画像のサイズ変更でプレイ導線が崩れていないか。
- 小画面でもヒットバー周辺が窮屈になっていないか。

#### 完了条件

- 釣り画面で魚表示と主要操作が画像ベースになっている。
- ゲームプレイに必要な情報の視認性が保たれている。

- `EncyclopediaView`
- `EncyclopediaCard`
- `LockedFishCard`
- `RarityStars`

#### 目的

- 図鑑カードを画像中心の一覧表示にする。

#### 差し替え候補

- 未発見表示: `SecretFish` または `Blok`

#### レビュー観点

- 一覧で魚ごとの判別がしやすいか。
- 未発見状態と発見済み状態の差が十分か。
- 画像適用後もカード密度が高くなりすぎていないか。

#### 完了条件

- 図鑑一覧が魚画像ベースで閲覧できる。
- 未発見カードとレアリティ表示が画像で統一されている。

#### 対象

- `ShopView`
- `ShopBaitCard`

#### 目的

- 餌カードと購入状態をアセットベースの UI に置き換える。

- 餌画像: `Esa`、`Ebi`、`Sakana-Esa`

- 状態差分が一目で判別できるか。
- `購入` と `選択` の操作ミスを誘発しないか。
- ボタン画像の意味がテキストなしでも補強されているか。

#### 完了条件

#### 差し替え候補

#### 作業内容

- `もう一度釣る` と `ホームへ戻る` を画像導線へ差し替える。
- 失敗時も情報欠落なく状態が伝わるよう補助画像を検討する。

#### レビュー観点

- 成功・失敗の判別が瞬時にできるか。
- CTA ボタンが十分に目立つか。
- オーバーレイ全体が過密になっていないか。

#### 完了条件

- 結果画面で行動導線と結果表示が画像ベースになっている。

## レビュー運用

- 各 Task 完了後に差分レビューを実施する。
- レビュー承認後に次の Task へ進む。
- 未承認の Task は次画面へ進めない。
- レビュー指摘は対象 Task 内で解消し、別画面には持ち越さない。

## 作業メモ

- 画像差し替えに合わせて、魚や餌の `assetName` 設計見直しが必要になる可能性がある。
- 現在 `アジ` に対応する専用画像が見当たらないため、暫定的に `Fish` を利用するか、後続でアセット追加判断が必要。
- 未使用画像の `Buri`、`Isaki`、`Kanpati` は、将来の魚種追加タイミングで再評価する。
