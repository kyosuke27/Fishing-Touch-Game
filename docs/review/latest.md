# AI機能提案

## アプリ理解
「ツリゲータッチ」は、ガラケー時代の雰囲気をスマホ向けに再現したタップ型のカジュアル釣りゲームです。釣りミニゲーム、魚図鑑、釣果履歴、餌ショップなどを備え、JSONによるローカル永続化とAdMob広告を組み込んでいます。シンプル操作で短時間プレイを想定しており、収集要素（図鑑・レア魚）で継続率を高める設計です。

### IssueNo: FP-001
- [ ] 選択: FP-001
- 機能名: 毎日ログインボーナス（デイリーボーナス）＋ローカル通知リマインダ
- 概要: 毎日アプリを開いた回数に応じてコインや餌を配布する仕組みを追加し、起動を促すローカル通知（任意同意）を実装する
- 課題: 短期の継続率が低いとリテンションに課題。広告/収益の機会を逃している
- 提案内容:
  - 起動時に「連続ログイン日数」を判定してボーナスを付与
  - 7日ごとや連続ボーナスのUIを簡単に表示（リザルトオーバーレイにバッジ）
  - ユーザーが許可した場合は毎日任意時刻にローカル通知で「今日のボーナス」を送信
- ユーザー価値: 毎日のログイン動機づけ、コイン・餌の自然な供給で課金ハードルを下げる。継続率向上。
- 実装難易度: 🟩 Low
- 優先度: P0
- 想定工数: 1d
- Issueタイトル案: 「デイリーボーナス機能とローカル通知によるリマインダを追加する」
- ラベル案: enhancement, retention, monetization
- 受け入れ条件:
  - 連続ログイン日数をローカルJSONで保存・更新できる
  - 起動時に適切なボーナス（コイン/餌）を付与してリザルト表示できる
  - ローカル通知の許可フローと任意オン/オフ設定画面がある
  - ログイン履歴はdeveloper toolsで確認できる（JSON）
- 実装メモ:
  - DomainにDailyRewardエンティティ、UseCaseで付与ロジックを実装
  - Persistenceは既存のuser_game_data.jsonにフィールド追加
  - LocalNotificationはUNUserNotificationCenterを使用、設定画面はHomeに簡易トグル
  - 文言はLocalizable.xcstringsへ追加

- 機能名: デイリーミッション（簡易実績）と報酬
- 概要: 「今日のミッション」を3つ程度（例：1回釣る、特定の餌で釣る、コインを100獲得）提示して達成でコイン/餌を付与する仕組み
- 課題: 単発プレイが中心で、継続的に遊ばせる誘因が弱い
- 提案内容:

  - ミッション達成判定はローカルで行い、報酬を即時付与
  - ミッションはランダム or ルールベースで組み合わせ（ローカルJSONで定義）
- ユーザー価値: 目的意識を与え短時間でもやることを作る。リテンションと広告/課金の接点増加。
- 実装難易度: 🟨 Middle
- 優先度: P0
- 想定工数: 1–2d（1.5d想定 → 1dか2dの選択肢はプロジェクト次第）
- Issueタイトル案: 「デイリーミッション（短期達成型実績）を追加する」
- ラベル案: feature, retention, game-design
- 受け入れ条件:
  - ミッション定義をLocal JSONで持ち、Home画面で今日のミッションが表示される
  - 達成判定が行われ、達成時に報酬が付与される
  - ミッションの状態はuser_game_data.jsonに保存される（達成済/未達成/報酬受取）
  - ミッションUIは英日ローカライズ対応
- 実装メモ:
  - UseCase: EvaluateMissionUseCase、Repositoryは既存のPersistenceを流用
  - シンプルUI（横スクロールカード）で実装し、詳細はリザルト画面に遷移可能
  - 将来的に実績画面と連携できる設計にしておく

### IssueNo: FP-003
- [ ] 選択: FP-003
- 機能名: 報酬型広告（Rewarded Ad）で餌やコインを獲得
- 概要: ユーザーが視聴した報酬型Adで餌やコインを獲得できるボタンを実装（AdMobのRewarded）
- 課題: 現状はバナー・インターのみで、ユーザーに直接的な広告価値交換手段がない
- 提案内容:
  - ショップや釣り画面の「動画を見て餌を獲得」ボタンを追加
  - AdMobのRewardedAdを実装し、視聴完了で報酬を付与
  - 視聴回数上限（例：1日3回）をローカルで管理
- ユーザー価値: 無料ユーザーでもプレイ時間を延ばせる。広告単価が高く収益化向上。
- 実装難易度: 🟨 Middle
- 優先度: P0
- 想定工数: 1–2d
- Issueタイトル案: 「報酬型広告で餌・コインを配布する（AdMob Rewarded導入）」
- ラベル案: monetization, admob, feature
- 受け入れ条件:
  - RewardedAdのロード・表示ロジックを追加し、テストIDで動作確認できる
  - 視聴完了で所定報酬（餌1個等）が付与される
  - 日次視聴上限のローカル管理が行われる
  - 失敗時のフォールバック（ロード失敗時はUIで案内）を実装
- 実装メモ:
  - Presentation/Shared/Admob に RewardedAdProvider を追加
  - AdMob SDKは既に導入済みなので、Rewardedクラスの追加のみ
  - ユーザー同意やATTrackingの確認フローを行った上で表示
  - 報酬ポップアップは既存のリザルトコンポーネントを流用

  - 小さいエフェクトを釣り中にも入れて操作感を向上
- ユーザー価値: 「嬉しい」体験の増加でリピートしやすくなる。UI/UX改善としてポートフォリオ評価に有利
- 実装難易度: 🟩 Low
- 優先度: P0
- 想定工数: 0.5d
- Issueタイトル案: 「レア魚獲得時の演出（アニメ・コンフェッティ・Haptic）を追加」
- ラベル案: ui, ux, polish
- 受け入れ条件:
  - 新種/レア判定時に視覚・触覚フィードバックが発生する
  - コイン増加がアニメで視覚的にカウントされる
  - パフォーマンスへの悪影響がない（FPS低下がないこと）
- 実装メモ:
  - SwiftUIのanimation + CAEmitterLayerの簡易実装（UIViewRepresentable）を併用
  - HapticはUIFeedbackGeneratorを利用
  - 演出は設定でオン/オフ切替可能にする（設定はHomeに簡易追加）

  - StoreKitでテスト用プロダクトを取得・購入できる（Sandboxで確認）

## 優先順位
1. FP-001: デイリーボーナスは実装が簡単で継続率に直結するため最優先。ローカル通知で復帰率も期待できる。  
2. FP-003: 報酬型広告は収益単価が高く、無料ユーザーの継続も促すため優先度高。既存AdMob基盤があるので実装効率も良い。  
3. FP-005: レア演出は短時間でユーザー体験が劇的に向上するため早めに入れる。ポートフォリオとしても見栄え向上。  
4. FP-004: シェア機能は短工数で自然流入を期待できる。  
5. FP-006: 図鑑フィルタは将来の拡張を見据えて有用で、実装も軽い。  
6. FP-002: デイリーミッションはリテンション効果が高いが設計の幅があるため中程度の工数を見込む。  
7. FP-007: IAPは収益化に直結するが、StoreKit周りの手間と審査対応が必要なため工数・リスク高め。リリース準備が整ったタイミングで実施。

## 今回は見送る案
- サーバー連携によるクラウド保存・ランキング（バックエンドが必要で工数が大きい）  
- 釣り場や季節・時間帯による魚出現の大規模追加（設計とマスタ改修で時間がかかる）  
- フル実装の広告同意管理（UMP）やプロダクション用広告ID周りの公開設定（重要だが作業範囲が広い）  
- リアルタイムプッシュ通知サーバ連携（APNs + サーバ必須でコスト高）  
- マルチユーザー機能やフレンド対戦（サーバ設計が必要）
